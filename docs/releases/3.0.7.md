# Virgos-MC 3.0.7 — startup fix and installer 26

Server release **3.0.7** keeps client compatibility **3.0.6** and ships **installer 26**. The server startup fix needs no client mod update. Run the new installer against the existing game folder to apply the graphics adjustment.

## Fix
Generated-resource reads now capture bytes and invalidate their lazy cache under the same per-resource monitor. This prevents the reproduced null-cache race without disabling datapacks, replacing bad resources with empty data, or retaining forgotten data. Recipe-stream settings remain unchanged.

## Verification
- Deterministic reproduction against installed KubeJS bytecode failed before the guard and passed after it.
- Full Gradle checks and independent packaged-bytecode probes passed; unrelated resource caches remain parallel.
- Real public restart reached `Done`, logged actual guard activation, loaded all five KubeJS scripts without errors, and answered advancing game-time queries.
- Complete verified backup precedes deployment; no Minecraft client was launched.

See [verification record](3.0.7-kubejs-startup.json) for hashes, backup and runtime evidence. Concurrent resource export is outside this startup-only guard.

## Client installer 26
- Forces `mipmapLevels:0` on fresh installs and existing clients during installation or repair. Other graphics preferences, resource packs and custom controls are retained.
- Existing clients must run this updated installer; publishing alone cannot change their local settings. Reapplying is idempotent; verify-only does not rewrite options.
- Installer and MRPack retain client identity **3.0.6**, compatible with server **3.0.7**. The MRPack contains fresh-install defaults; existing-client migration requires the Windows installer.
- Both archives include pinned corresponding sources. Exact package hashes are in `release.json` and [installer verification](3.0.7-client-installer.json). No Minecraft client was opened.
